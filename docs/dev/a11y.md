# Accessibility notes: graph pages and DeepDive

Scope: `xray-graph.html`, `xray-graph-nextui.html` and the DeepDive panel they open
(rendered by `xray-core.js` / `xray-api.js`). Checked on 2026-11-03 with headless Chromium on a
3-router topology rendered from each template (synthetic state, and with the grey "sample" filter
removed for contrast measurements).

Target: WCAG 2.1 AA — 4.5:1 for normal text, visible keyboard focus, every control usable
from the keyboard, colour never the only signal for a state.

## What was checked

| Check | Result before | Now |
|---|---|---|
| Open a router's DeepDive from the keyboard (`xray-graph.html`) | Not possible: overview nodes were `<div onclick>`, not in the Tab order | Nodes are `role="button"`, `tabindex="0"`, labelled "Open DeepDive for &lt;name&gt; (&lt;kind&gt;)"; Enter or Space opens |
| Open a router's DeepDive from the keyboard (`xray-graph-nextui.html`) | Not possible: only the whole NeXt UI canvas took focus; nodes are SVG `<g>` with no focus support | Each `g.node` gets `tabindex="0"`, `role="button"`, an aria-label; Enter or Space opens (same path as a click, including the scroll) |
| Escape closes the DeepDive | Already works (engine listener in `_xrayWireOssDeepClose`, active on OSS pages) | Unchanged. Tab to a node + Enter reopens. Pressed right after the DeepDive opens, Esc sometimes does not close it (seen before and after this change, in English and Japanese); pressing it again closes it |
| Close button | "✕ Close" has text; in Tab order | Unchanged |
| Focus visibility | Browser default ring only (thin, low contrast on the dark page); NeXt canvas had `outline:none` | 2px X-Ray teal outline on every focusable element in the page (`.wrap :focus-visible`); focused NeXt node gets a ring around the icon; NeXt canvas gets an outline |
| Icon-only buttons | Preview pop-up close (`×`) had only a `title` | `aria-label` added ("Close" / 閉じる). No other icon-only buttons found |
| Text contrast, dark page | `.hint` `#607d8b` on `#0f1318` = 4.26:1 (NeXt page) | `#78909c` = 5.56:1 (same grey family) |
| Text contrast, DeepDive panel | `.de-dim` (interface addresses) = 2.38:1; `.de-r1-sub` ("Router — Internal View") = 3.0:1 | Same skin colour at 0.7 alpha instead of 0.35 / 0.4: 6.6:1 and 7.4:1 (signature skin), ≥5.1:1 with the containerlab skin |
| Text contrast, light overview bar (NeXt page) | containerlab blue `#0386d2` on white = 3.9:1 (lab name, Horizontal / Vertical, node names) | One step darker `#0273b5` = 5.1:1 (4.9:1 on the bar's `#f8fafc`) |
| Other measured page text | Footer `#6f8291` 4.68:1, subtitle/kind `#78909c` ≥5.17:1, `.sub` `#90a4ae` 7.2:1, validate note `#78909c` on `#1c2736` 4.50:1 | Pass, unchanged |
| Selected state is not colour-only | Selected overview node (red) and current peer-pair / layout button (filled) were colour-only for assistive tech | `aria-pressed` on overview nodes, peer-pair buttons and Horizontal / Vertical (both `false` until a layout is chosen). The DeepDive title also names the open router |
| Focus moves the overview (`xray-graph-nextui.html`) | - | Tabbing to a node scrolled the overview frame and hid the Horizontal / Vertical bar; the frame is now put back on focus |
| netlab validate list | Passed and not-yet tests both show ✓; only green vs grey differs | Each row's mark now has a screen-reader state word (passed / not yet / waiting / not run yet / not checked / skipped; Japanese when the page is in Japanese); the glyph is `aria-hidden` |

The overrides are scoped to these two pages. The fixes for the engine's dim text are page CSS in
the two templates, so other pages that load `xray-core.js` look the same as before.

## Left undone (bigger than a small fix)

- **Validate list, visible text.** Sighted users still tell "passed" from "not yet" by green vs grey
  only (same ✓ glyph, by design). A visible state word or a different glyph would change the
  agreed look. The hover `title` and the new screen-reader text carry the state.
- **NeXt overview colours.** netlab validate marks colour links (green / red) and nodes (green /
  red; grey = not read). Failed links are also dashed, but node colours have no text on the
  overview itself. The same facts are in the validate list and in the per-router note under the
  overview.
- **DeepDive internals.** The engine draws adjacency and process state with colour, glow and
  animation. Most states also show a state word (e.g. OSPF neighbour state), but there is no full
  audit of every panel, of the Skin popover, or of `prefers-reduced-motion`. The engine is shared
  with other pages, so changes there need their own pass.
- **aria-labels in `xray-graph.html` are English only** ("Open DeepDive for …"), like the existing engine labels.
  On `xray-graph-nextui.html` the node labels follow the page language (English / Japanese).
- **Problem band `<code>` click-to-copy** works with the mouse only (no focus or key handler).
- **Arrow-key navigation** between overview nodes, and moving focus into the DeepDive when it opens,
  are not implemented. Tab order follows the node order.
- **NeXt UI's own controls** (zoom / pan toolbar, tooltips) are third-party and left as shipped.

## How the checks were run

The templates were rendered by replacing `{{ .Name }}` / `{{ .Data }}` with a small topology and
served with `static/` mapped to the repo root. A Playwright script then pressed Tab through each
page, recorded the focused element, its accessible name and its computed outline, pressed
Escape / Enter / Space, and computed the contrast of every visible text node against its effective
background. These scripts are not part of the repo.
